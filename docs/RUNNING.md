# Running Watchdog

A practical guide to running the Watchdog app locally. Watchdog is a **React Native + Expo
(TypeScript)** app; right now it is the **Phase 1 app shell** — navigation, design system, and a
demo dashboard with **simulated** data. There is no real backend, camera, or AI yet.

> New here? Read the [README](../README.md) first, then this guide.

---

## 1. Prerequisites

- **Node.js ≥ 20.19.4** (the app targets React Native 0.86). Check with `node -v`.
  - _This machine:_ Node lives in `~/.local` (v24.x), already on your `PATH` — nothing to install.
- **npm** (ships with Node). This project uses **npm** — don't mix in yarn/pnpm/bun.
- **A way to preview the app** — pick one:
  - **Expo Go on a phone** (easiest, no setup): install "Expo Go" from the App Store / Play Store.
  - **iOS Simulator** (macOS only): install Xcode, then open it once to accept the license.
  - **Android emulator**: install Android Studio and create a virtual device.
  - **Web browser**: no extra setup.

You do **not** need Watchman, CocoaPods, or a native build — this is the Expo managed workflow.

---

## 2. Install dependencies

From the project root:

```bash
npm install
```

This installs Expo, expo-router, React Native, the Manrope font package, and dev tooling. Run it
again only when dependencies change.

---

## 3. Start the app

```bash
npm start
```

This launches the **Expo dev server** (Metro) and shows a QR code plus a menu. Then open the app
on your chosen target:

| Target | How |
|---|---|
| **Phone (Expo Go)** | Scan the QR code with your phone's camera (iOS) or the Expo Go app (Android). Phone and computer must be on the same Wi‑Fi. |
| **iOS Simulator** | Press **`i`** in the terminal (macOS + Xcode). |
| **Android emulator** | Press **`a`** in the terminal (emulator running). |
| **Web browser** | Press **`w`**. |

Or start straight into one platform:

```bash
npm run ios       # iOS Simulator
npm run android   # Android emulator
npm run web       # browser
```

Press **`r`** to reload, **`m`** for the dev menu, and **`Ctrl+C`** to stop the server.

---

## 4. What you should see

1. A brief splash while the **Manrope** font loads.
2. The **Welcome** screen — the Watchdog wordmark, tagline, and an **"Enter demo mode"** button.
3. Tap it to enter the **bottom-tab** app:
   - **Home** — a dashboard: a greeting, three status cards, and a recent-activity list (all
     **simulated** demo data, labeled as such).
   - **Cameras / Map / Review / Profile** — designed placeholder screens with empty states
     describing what will live there in later phases.

Everything is **demo mode** with simulated cameras, detections, and alerts — there is no sign-in,
backend, or real device yet.

## 6. Troubleshooting

- **Stale bundle / weird Metro errors** → clear the cache: `npx expo start -c`.
- **"Unable to resolve module" right after pulling** → re-run `npm install`.
- **Phone can't connect (Expo Go)** → ensure the phone and computer share Wi‑Fi; try the
  tunnel connection: `npx expo start --tunnel`.
- **Typed-route type errors in your editor** → they generate on first `expo start` (into the
  git-ignored `.expo/types`); `npm run typecheck` passes without them.
- **`watchman` warning** → harmless; Metro falls back to Node's file watcher.
- **Wrong Node version** → use Node ≥ 20.19.4 (see Prerequisites).

---

## 7. Notes

- **Managed workflow:** the `ios/` and `android/` folders are generated by `expo prebuild` and are
  git-ignored — you don't need them to run in Expo Go / Simulator / web.
- **Environment variables:** none are needed for the demo. If/when real integrations arrive, copy
  `.env.example` → `.env.local` (only `EXPO_PUBLIC_*` keys belong in the app).
- **Where the code lives:** routes in `app/`, shared UI in `src/components/`, design tokens in
  `src/theme/`, demo data in `src/mock/`. See
  [app_walkthrough](obsidian/10%20App%20Walkthrough/app_walkthrough.md) for a guided tour.
