# Running Frontline

A practical guide to running the Frontline app locally. Frontline is a **React Native + Expo
(TypeScript)** app that helps **veterans find benefits and local resources**. The project was just
reframed from the previous product: documentation, `CLAUDE.md`, and app config are now
Frontline, and the reusable design system + app shell carry over. **Frontline feature screens are
built next** (starting with the resource data model + service) — until then the running app shows
the reused shell and the legacy screens. There is no real backend or live AI yet.

> New here? Read the [README](../README.md) first, then this guide.

---

## 1. Prerequisites

- **Node.js ≥ 20.19.4** (the app targets React Native 0.81 / Expo SDK 54). Check with `node -v`.
  - _This machine:_ Node lives in `~/.local` (v24.x), already on your `PATH` — nothing to install.
- **npm** (ships with Node). This project uses **npm** — don't mix in yarn/pnpm/bun.
- **A way to preview the app** — pick one:
  - **iOS Simulator** (macOS, primary): a **development build** (see §3). Needs full **Xcode**
    (not just Command Line Tools) and **CocoaPods** — see [Development build prerequisites](#3a-development-build-first-time-setup).
  - **Android emulator**: install Android Studio, create a virtual device, then `npm run android`.
  - **Web browser**: no extra setup (`npm run web`).

Frontline now uses a **development build** (an `expo-dev-client` app compiled from this project),
not Expo Go. `expo start` still runs the same **dev server** (Metro); the difference is the
runtime — a native app we build once instead of Expo's shared sandbox. This lets us add native
modules the sandbox can't carry. The Expo managed workflow still applies: `ios/`/`android/` are
generated by `expo prebuild` and git-ignored.

> **Legacy:** the app is still Expo-Go-runnable today (SDK 54, no native module yet requires the
> dev build), so scanning the QR in Expo Go continues to work as a fallback until Phase 6+ native
> modules land. The dev build is now the primary path.

## 2. Install dependencies

From the project root:

```bash
npm install
```

This installs Expo, expo-router, React Native, the Manrope font package, and dev tooling. Run it
again only when dependencies change.

---

## 3. Start the app

Once the development build is installed on your Simulator/emulator (first-time setup below):

```bash
npm start
```

This launches the **Expo dev server** (Metro). With `expo-dev-client` installed it prints
**"Using development build"** and targets your installed dev build (not Expo Go). Press **`i`** /
**`a`** to open it in the iOS Simulator / Android emulator, **`w`** for web, **`r`** to reload,
**`m`** for the dev menu, **`Ctrl+C`** to stop.

### 3a. Development build (first-time setup)

The dev build must be **compiled once** before `npm start` has anything to open. On macOS for iOS:

1. Install prerequisites (one time):
   - **Full Xcode** from the Mac App Store (~7 GB). Then:
     ```bash
     sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
     sudo xcodebuild -license accept
     ```
     Open Xcode once so it installs an iOS Simulator runtime.
   - **CocoaPods** — the macOS **system Ruby is 2.6**, which is too old for current CocoaPods
     (its dependencies now require Ruby ≥ 3.1, so `gem install cocoapods` dead-ends on
     `ffi`/`securerandom`). Install it via **Homebrew**, which bundles its own modern Ruby:
     ```bash
     /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
     echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile   # Apple Silicon
     eval "$(/opt/homebrew/bin/brew shellenv)"
     brew install cocoapods                                            # then: pod --version
     ```
2. Build + launch the dev build:
   ```bash
   npm run ios       # = expo run:ios — prebuilds ios/, pod install, compiles, boots Simulator
   npm run android   # = expo run:android (needs Android Studio)
   npm run web       # browser (no build; Map tab shows a placeholder)
   ```
   The first compile takes several minutes; later JS changes reload instantly via `npm start`.

Rebuild the dev build (`npm run ios`) only when native config/dependencies change — otherwise
just `npm start`.

## 4. What you should see

> **Interim state (post-reframe):** Frontline's feature screens haven't been built yet — only docs
> and app config changed. What launches today is the **reused app shell** plus the previous
> product's screens (being replaced per the [Feature Priority Order](obsidian/01%20Product/Feature%20Priority%20Order.md)).
> Treat the current screens as scaffolding, not Frontline behavior.

1. A brief splash while the **Manrope** font loads.
2. The **Welcome** screen, then the reused **bottom-tab** shell.
3. The design system is real and carries over (dark navy theme, typography, cards, empty/loading/
   error states). The **Frontline** experience — "What do you need help with?", resource list/map,
   detail pages, AI next-step plans and call scripts — is built in the upcoming phases.

> **Runtime:** the primary target is the **development build** on the iOS Simulator (§3a); the map
> renders via **Apple Maps** there, no API key needed. On the **web** preview the map shows a
> placeholder (react-native-maps is iOS/Android only).

Everything is **demo/simulated** — there is no sign-in, backend, or live AI yet.

## 6. Troubleshooting

- **Stale bundle / weird Metro errors** → clear the cache: `npx expo start -c`.
- **"Unable to resolve module" right after pulling** → re-run `npm install`.
- **Phone can't connect (Expo Go)** → ensure the phone and computer share Wi‑Fi; try the
  tunnel connection: `npx expo start --tunnel`.
- **Typed-route type errors in your editor** → they generate on first `expo start` (into the
  git-ignored `.expo/types`); `npm run typecheck` passes without them.
- **`watchman` warning** → harmless; Metro falls back to Node's file watcher.
- **Wrong Node version** → use Node ≥ 20.19.4 (see Prerequisites).

## 7. Notes

- **Managed workflow + dev client:** the `ios/` and `android/` folders are generated by
  `expo prebuild` (run automatically by `expo run:ios`/`run:android`) and are git-ignored. The
  runtime is now a **development build** (`expo-dev-client`); Expo Go remains a fallback.
- **Environment variables:** none are needed for the demo. If/when real integrations arrive, copy
  `.env.example` → `.env.local` (only `EXPO_PUBLIC_*` keys belong in the app).
- **Where the code lives:** routes in `app/`, shared UI in `src/components/`, design tokens in
  `src/theme/`, demo data in `src/mock/`. See
  [app_walkthrough](obsidian/10%20App%20Walkthrough/app_walkthrough.md) for a guided tour.
